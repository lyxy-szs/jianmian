## 1. 项目目标与交付边界

面向企业真实招聘面试，解决两位考官记录分散、评价难汇总的问题。以单场面试为单位，通过实时便签墙、独立讨论区、分别评价及主考官最终确认，形成可追溯的面试结果。

本次交付物为可落实的项目计划书；本文列出的源代码、CLI 命令、页面和自动化测试均为待实施内容，尚未创建或运行。后续 MVP 必须实现本文所有核心功能，不以静态页面或角色切换模拟替代真实协作。

最新需求覆盖早期的双角色设计：提供主考官、副考官、面试人三个不同访问链接，并提供简易 CLI 控制台。浏览器是业务操作入口，CLI 是启动和管理入口，无需让面试人操作命令行。

## 3. 产品定位与 MVP 范围

### 3.1 已确认的产品决策

- 面向通用岗位，以单场面试板组织内容，不做候选人列表和招聘岗位管理。
- 两位考官实时看到彼此的便签、个人评价和讨论内容。
- 创建时填写候选人姓名、应聘岗位、主考官姓名、候选人简介、本次面试重点。
- 便签自由记录后归类；默认“亮点 / 疑虑 / 待验证”，另有不可删除的“未分类”。
- 分组可新增、改名、删除；删除需确认，组内便签移入“未分类”。
- 双方均可移动便签，只能修改、删除自己创建的便签；显示作者和创建时间。
- 便签支持“重要”“需要讨论”标记及筛选；修改标记同样属于作者编辑权限。
- 考官讨论区独立于便签墙，支持实时文字、历史消息、引用便签并定位、回复消息。
- 每位考官选择“强烈推荐 / 推荐 / 待定 / 不推荐”，填写理由并提交。
- 两人提交后，主考官才能确认最终结论；两人等级不同，必须补充分歧说明。
- 完成后整体只读，主考官可重新开启；提供在线总结和 Markdown 导出。
- 电脑端完整操作，手机端只读；默认浅色，提供深色主题。
- 自动保存、浏览器记住身份、支持离线编辑与恢复同步。
- 同时移动按最后一次有效操作处理；失效的离线内容保留为本地草稿。
- 提供空白创建和虚构示例；示例仍走真实加入及协作流程。

### 3.2 新增第三角色的实施假设

用户已明确需要面试人独立界面，但尚未指定面试人侧业务细节。为使第一版可直接实施，采用以下可调整基线：

1. 面试人可以看到自己的姓名、应聘岗位、公开面试说明、面试状态，并确认“准备就绪”。
2. 候选人简介、本次面试重点默认属于内部资料，不向面试人展示；另设选填的“公开面试说明”。
3. 面试人不能访问便签、内部讨论、考官评价、分歧说明、最终录用建议和报告。
4. 面试结束时，仅向面试人显示“本次面试已结束”，不自动告知内部录用结论。
5. 音视频、在线答题、面试人与考官文字聊天均不包含在本版。面试沟通使用现场或既有会议工具。

三角色是实际服务端权限隔离；不能通过隐藏前端组件来代替。

## 4. 角色、链接和身份

### 4.1 页面入口

以下为拟定路由，默认地址为 `http://127.0.0.1:4310`，端口可配置。

| 入口 | 示例路径 | 用途 |
| --- | --- | --- |
| 创建页 | `/` | 创建空白面试或加载示例 |
| 主考官 | `/interviews/:id/lead` | 面试板、审核加入、最终结论及重新开启 |
| 副考官邀请 | `/join/:inviteToken` | 输入姓名并申请加入，批准后进入副考官页面 |
| 副考官 | `/interviews/:id/co` | 面试板、讨论、个人评价 |
| 面试人邀请 | `/candidate/join/:inviteToken` | 领取面试人身份，进入候选人页面 |
| 面试人 | `/interviews/:id/candidate` | 公开信息、等待及准备状态 |
| 结果页 | `/interviews/:id/report` | 仅考官可查看与导出 |

CLI 或创建页输出三个不同的初始访问链接。主考官初次领取身份也使用一次性随机令牌；领取后跳转到不含令牌的标准地址。任何人仅猜到标准路径都不能获得角色权限。

### 4.2 加入与恢复规则

- 每场固定一个主考官席位、一个副考官席位和一个面试人席位；“两人协作”的原限制指两位考官。
- 副考官申请未通过前只能看到申请状态，不返回候选人内部数据；主考官可以批准或拒绝。
- 审核以服务端事务占位，防止并发批准多个副考官。
- 面试人通过专属邀请领取该场候选人席位，不进入考官审核队列。
- 身份以服务端会话和 HttpOnly、SameSite Cookie 保存；浏览器本地存储只保存界面偏好、缓存和离线队列，不保存角色认证密钥。
- Cookie 有效且未被撤销时，同一浏览器通过标准链接返回可恢复身份。换浏览器或清除 Cookie 需重新邀请。
- 同源浏览器环境采用一个活动身份，因此验收使用普通窗口和无痕窗口；第三角色使用另一个浏览器或独立配置文件。
- 重新邀请必须撤销旧席位会话、关闭旧实时连接，并保留历史内容作者标识；旧客户端队列不得继续写入。
- 主考官身份丢失时，由本机 CLI 生成新的主考官恢复链接；已被领取的令牌不可再次用于登录。
- 链接使用强随机令牌、一次性兑换，重新生成时旧邀请失效；默认有效期 24 小时，可配置。
- 日志不打印完整邀请令牌；CLI 用户主动执行链接命令时可在本地终端显示，页面不向面试人暴露其他角色链接。

### 4.3 权限矩阵

| 操作 | 主考官 | 副考官 | 面试人 |
| --- | --- | --- | --- |
| 查看内部候选人资料、全部便签和讨论 | 是 | 是 | 否 |
| 新建便签、编辑/删除本人便签 | 是 | 是 | 否 |
| 移动任意便签、管理分组 | 是 | 是 | 否 |
| 发送讨论、引用便签、回复消息 | 是 | 是 | 否 |
| 提交或修订自己的评价 | 是 | 是 | 否 |
| 查看两人的实时评价 | 是 | 是 | 否 |
| 审核副考官、重新邀请席位 | 是 | 否 | 否 |
| 确认结论、重新开启 | 是 | 否 | 否 |
| 查看总结、导出报告 | 是 | 是 | 否 |
| 查看公开信息及面试状态 | 是 | 是 | 是 |
| 切换候选人准备状态 | 否 | 否 | 仅本人 |

以上写操作还受面试板状态约束。完成后禁止所有业务写入，唯一例外是主考官重新开启；身份恢复和读取不属于业务编辑。

## 5. 核心业务流程与状态

### 5.1 主流程

1. 创建面试：填写内部资料和可选公开说明，选择空白或示例。
2. 获取链接：进入主考官页面，分享副考官邀请链接和面试人链接。
3. 加入：副考官提交姓名并等待审批；面试人领取席位并确认准备状态。
4. 协作：考官实时记录、归类便签，标记筛选，在独立文字区讨论。
5. 评价：两位考官分别提交推荐等级和非空理由；已提交评价可在结束前修订。
6. 确认：主考官选择最终推荐等级、填写最终理由；存在分歧时补充分歧说明。
7. 完成：面试板整体只读，在线查看总结或导出 Markdown；候选人仅看到结束状态。
8. 必要时重新开启：恢复评估，原最终报告保留为历史版本；两位考官须重新确认评价，再生成新版本结论。

最终结论沿用四档推荐等级，属于内部招聘建议，不发送 offer、不自动拒绝候选人。

### 5.2 状态与校验

面试板：`open → evaluating → completed`；主考官可将 `completed → evaluating`。

- 创建后为 `open`；任一考官开始记录或评价后进入 `evaluating`。
- 未提交的个人评价为 `draft`，提交后为 `submitted`，服务端实时共享草稿内容与提交状态。
- 提交理由、最终理由去除首尾空白后必须非空；等级只能取四个合法值。
- 两人均为 `submitted` 才可完成；任一人修订评价内容，自己的状态回到 `draft`，须重新提交。
- 完成操作在单一事务内检查评价版本、权限、分歧说明和板状态，防止确认过程中评价被修改。
- 两人等级完全一致视为无分歧；任意不一致均须说明。
- 未处理完“待验证”便签不阻塞结论，报告如实保留。
- 面试人准备状态与结论条件分离，不要求候选人上线才能完成已有面试。
- 重新开启时，两份评价正文保留，但均恢复为草稿；原结论记录不被覆盖。

## 6. 页面与交互

### 6.1 考官页面

- 顶部：候选人、岗位、面试状态、主副考官在线状态、候选人准备状态、同步状态、主题切换。
- 主区：分组便签墙、新建便签、筛选、分组管理。新便签默认进入“未分类”。
- 右侧固定区：内部文字讨论；回复显示被回复消息摘要；引用便签可定位并高亮。
- 评价入口：展开侧面板，填写个人推荐等级和理由，查看对方实时评价及提交状态。
- 主考官额外操作：加入审核、邀请管理、确认结论、重新开启。
- 完成状态：明显展示只读原因，禁用编辑；手机布局采用纵向查看与折叠讨论区。

文字讨论先采用“回复某条消息＋引用预览”，按时间排列，不额外建设多层独立话题系统。消息仅发送后追加，不含消息编辑、撤回或附件。

便签被删除后，历史讨论保留引用摘要并显示“原便签已删除”，不再提供跳转；回复对象引用保留稳定 ID。

### 6.2 面试人页面

简洁单栏：姓名、岗位、公开说明、连接状态、面试状态、“我已准备好”按钮。未领取席位时显示加入页；已结束时显示结束提示。手机端只查看状态，准备按钮保留在电脑端。

候选人接口、初始页面数据、实时事件和离线缓存均只包含候选人允许访问的数据。

### 6.3 视觉与可用性

- 默认暖白背景、柔和彩色便签；深色模式独立配色，确保文字对比。
- 电脑端以 1280px 及以上为主要设计宽度；较窄桌面可收起讨论区，仍可完整操作。
- 手机端以约 390px 宽验证只读展示；服务端权限仍按角色执行，移动端只读属于产品交互限制。
- 拖动之外提供“移动到分组”菜单，便于键盘操作，也作为拖动失败时的替代入口。
- 不用颜色单独表达重要状态，标记同时有图标和文字。

## 7. 技术方案

### 7.1 推荐栈

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 服务端 | Node.js 24，ES Modules，内置 `http` | 环境已存在，避免依赖下载成为前置条件 |
| 数据库 | 内置 `node:sqlite`，本地 SQLite 文件 | 已实测可用，适合单实例 Demo |
| 实时推送 | SSE / EventSource；写入走 HTTP API | 双考官实时更新无需复杂服务器框架 |
| 浏览器端 | HTML、CSS、原生 JavaScript 模块 | 不依赖打包器，三角色页面共享组件 |
| 离线存储 | IndexedDB | 保存访问过的页面数据、草稿和待同步操作 |
| 页面缓存 | Service Worker，仅缓存静态壳 | 支持 localhost 下访问过的页面离线重开 |
| CLI | Node 内置 `util.parseArgs`、`readline` | 命令和交互菜单共享控制逻辑 |
| 验证 | `node:test`、内置 fetch、浏览器人工验收 | 核心规则可测试，UI 按真实流程验证 |

该方案为本机单实例 MVP，不依赖 Docker、云数据库、React 或全局安装工具。允许未来替换前端，但不把迁移列入本期任务。

### 7.2 服务约定

- 默认监听 `127.0.0.1:4310`，浏览器直接访问；端口被占用时明确报错并提示配置，不静默切换导致链接失效。
- 同一 Node 进程提供静态页面、业务 API、SSE 和本机管理 API。
- 写操作完成 SQLite 事务后，再向授权客户端推送事件；不将未持久化结果当成成功。
- API 使用同源会话，校验角色、面试状态、请求来源及输入长度；正文按纯文本渲染，拒绝 HTML 执行。
- 默认数据库位于项目 `data/interview.sqlite`，启用外键和 WAL，提供 schema 版本迁移。
- SSE 心跳、断线重连、游标补发；事件过期或游标失效时，重新拉取当前角色可见快照。
- 面试人使用单独的公开事件投影，禁止先推送全部事件再由客户端过滤。
- 本地管理接口需要启动时生成的管理凭据；凭据保存在仅当前用户可读的本地文件中，不放进浏览器资源。
- 服务进程是唯一数据库写入者；CLI 通过本机管理 API 创建和恢复面试，不直接并发修改数据库。
- 设置上限：便签正文 4000 字、消息 2000 字、评价理由 4000 字，API 请求体最大 128 KiB；超限明确提示。

### 7.3 网络边界

验收基线为同一电脑多个浏览器环境。跨设备、局域网发布及公网部署不作为本期验收条件；但使用普通 HTTP 页面和独立链接，不绑定桌面客户端。

后续若扩展为局域网，需要显式更改监听地址、处理 HTTPS 与浏览器离线能力要求，届时单独验收；不能将 `localhost` 链接发给另一台电脑并声称可用。

## 8. 数据结构与接口边界

### 8.1 主要数据表

| 表 | 主要字段 / 作用 |
| --- | --- |
| interviews | ID、候选人、岗位、内部简介、内部重点、公开说明、状态、revision、round |
| participants | 面试 ID、稳定席位 ID、角色、姓名、准备状态、会话代次 |
| sessions / invitations | 会话与令牌哈希、角色、有效期、兑换与撤销状态 |
| join_requests | 申请人、状态、请求 ID、审核结果 |
| groups | 名称、顺序、系统未分类标识、软删除时间 |
| notes | 作者席位、正文、分组、位置、重要/待讨论标记、版本、删除标记 |
| messages | 作者、正文、reply_to、note_id、引用摘要、时间 |
| evaluations | 面试轮次、考官、等级、理由、提交状态、版本 |
| decisions | 轮次、最终等级、理由、分歧说明、确认人、时间、报告快照 |
| events | 面试 ID、顺序号、事件类型、可见范围、负载 |
| applied_operations | 席位、opId、执行结果，防止离线重试重复写入 |

离线队列和冲突草稿存于浏览器 IndexedDB，以面试、身份及会话代次隔离。清除浏览器数据会丢失未同步草稿，界面须明确提示。

### 8.2 主要 API 组

- `POST /api/interviews`：创建空白或示例面试，返回主考官领取入口。
- `/api/invitations/*`：令牌兑换、候选人领取、重新邀请及撤销。
- `/api/interviews/:id/join-requests`：申请、查看本人申请状态、主考官审批。
- `/api/interviews/:id/snapshot`、`/events`：按身份读取快照与事件。
- `/api/interviews/:id/operations`：接收在线或离线操作，逐条返回成功、重复、冲突或无权限。
- `/api/interviews/:id/evaluations/me`：保存或提交自己的评价。
- `/api/interviews/:id/complete`、`/reopen`：结论确认及重新开启，在线事务执行。
- `/api/interviews/:id/report`、`/report.md`：考官读取当前总结、完成报告及导出。
- `/api/interviews/:id/candidate`：仅公开字段及本人的准备状态。
- `/api/admin/*`：本地 CLI 专用，独立管理凭据鉴权。

最终路由细节可在实现中调整，但权限、状态机和数据隔离不得降低。

## 9. 离线与冲突规则

离线是核心验收功能，不能只显示断线提示或简单重新加载页面。

### 9.1 同步协议

1. 本地操作立即写 IndexedDB，生成唯一 `opId`、实体 ID、依赖关系和本地顺序；界面显示“待同步”。
2. 请求附带基准版本、面试轮次和会话代次。服务端以事务验证、落库、记录 opId 并产生递增事件序号。
3. 重连先拉取当前状态及权限，再按队列顺序重放。新建便签后的移动、引用和回复必须等待其依赖操作成功。
4. 重试相同 opId 返回第一次结果，不生成重复便签或消息；同时有在线操作时统一通过服务端排队。
5. 每条操作独立返回结果；一条冲突不能阻塞整队，依赖失败项转入草稿。
6. 最后一次移动指服务端最后接受并提交的有效移动，不比较不可信的客户端时钟；离线移动重连后可能覆盖此前在线移动。

### 9.2 操作处理表

| 操作 / 情况 | 处理方式 |
| --- | --- |
| 新增便签、发送消息、修改本人便签、移动、管理分组 | 允许本地排队，恢复后校验同步 |
| 离线填写评价 | 保存草稿；“正式提交评价”需联网并得到服务端确认 |
| 审批、邀请、最终确认、重新开启、候选人准备确认 | 需在线完成；离线时解释原因，不假装成功 |
| 同一便签多人移动 | 按服务端最后一次有效提交的位置为准，展示最近移动人 |
| 本人多窗口修改同一正文 | 版本冲突时保留服务端版本，本地正文转草稿供复制 |
| 目标便签已删除 | 不复活便签，未同步正文或操作说明转为本地草稿 |
| 目标分组已删除 | 待同步便签或移动归入“未分类”，并提示调整原因 |
| 面试板已经完成 | 拒绝旧队列业务写入，文字转草稿，不触发自动重新开启 |
| 面试板已重新开启 | 旧轮次操作不自动写入新轮次，转草稿供人工确认 |
| 身份已被撤销 | 停止推送及队列写入，锁定旧身份缓存，提示重新邀请 |
| 引用的便签已删除 | 对已成功发送消息保留摘要；待发送消息保留正文并标明引用已失效 |

在线“已保存”、本地“待同步”、同步“失败待处理”须明确区分。关闭页面后，已进入 IndexedDB 的队列在同一浏览器返回时继续恢复；第一次访问从未缓存过的页面不保证离线可打开。

## 10. CLI 简易控制台

以下为拟实现命令，不代表现在即可执行。统一入口 `npm run console -- <command>`；无参数进入菜单。

```bash
# 安装项目无需第三方运行依赖；在项目目录启动服务
npm start

# 另一个终端打开交互菜单
npm run console

# 命令式入口
npm run console -- status
npm run console -- create
npm run console -- demo
npm run console -- links <interview-id>
npm run console -- reinvite <interview-id> --role co
npm run console -- reinvite <interview-id> --role candidate
npm run console -- recover-lead <interview-id>
npm run console -- report <interview-id> --output ./exports/report.md
npm run console -- stop
```

菜单提供：查看服务状态、创建面试、创建示例、输出三个角色入口、重新邀请、恢复主考官、导出报告、退出控制台。退出菜单不关闭服务；`stop` 或服务终端 Ctrl+C 才会关闭服务。

- `create` 逐项询问创建字段，可留空的字段明确提示；`demo` 使用确定的虚构资料，不生成已经登录的副考官。
- `status` 显示地址、端口、数据库路径、在线人数和已有面试 ID，用于本机管理；这不等于浏览器候选人列表功能。
- `links` 输出主考官标准入口及尚未领取的邀请链接；已经领取的席位只提示恢复方式，不重复输出已失效令牌。邀请原值仅在本机受保护状态文件保留至兑换或过期。
- `reinvite`、`recover-lead` 明确提示会撤销旧身份；交互菜单确认后执行，非交互模式需显式确认参数。
- `report` 在评估未完成时导出标注“评估中”的摘要，完成后导出对应最终报告版本。
- 服务未运行、管理凭据无效、端口占用、数据库不可写时，以清晰中文和非零退出码退出。
- 不在本期提供删除全部数据、自动清库、隐式覆盖已有报告等破坏性快捷操作。

## 12. 开发里程碑与工期估算

以一名熟悉 Node 和浏览器开发的开发者为估算基准，总计约 **10～15 个工作日**，不是固定交付日期。离线同步是主要不确定项；端口权限解决等待不计入开发量。所有核心功能必须完成，不能以里程碑中的中间版本冒充最终 MVP。

| 阶段 | 估算 | 产出 | 完成条件 |
| --- | --- | --- | --- |
| M0：运行条件与骨架 | 0.5～1 天 | HTTP 服务、SQLite 文件、静态页、脚本 | 可启动、浏览器可访问、重启后数据保留 |
| M1：三角色与 CLI | 1.5～2 天 | 三个入口、身份恢复、审批、候选人页、菜单 | 三个浏览器身份隔离；候选人无法读取内部数据 |
| M2：协作工作区 | 2～3 天 | 便签、分组、标记、SSE、讨论引用与回复 | 两个考官窗口真实同步；作者权限有效 |
| M3：评价与报告 | 1～1.5 天 | 独立评价、最终确认、只读、重新开启、报告 | 状态机及分歧校验通过；导出与页面一致 |
| M4：离线和冲突 | 3～4 天 | 缓存、队列、幂等、恢复、冲突草稿 | 断网、重连、重试、删除冲突及结束冲突全部通过 |
| M5：整体验收 | 2～3 天 | 深浅主题、手机只读、示例、测试、README | 下节所有必过项完成，缺陷清单关闭 |

实施顺序先打通一条在线主流程，再补完整离线协议。每阶段验证功能边界，避免直到最后才发现权限或数据结构不支持同步。

## 13. MVP 验收清单

### 13.1 三角色与 CLI

- [ ] 普通终端可启动服务，电脑浏览器访问配置地址成功。
- [ ] CLI 无参数菜单、创建、示例、状态、链接、重新邀请、恢复主考官、导出及停止均可用。
- [ ] 主考官、副考官、面试人分别通过不同链接进入；刷新恢复当前身份。
- [ ] 副考官未批准、被拒绝或席位已占用时不能读取内部数据。
- [ ] 猜测主考官 URL、修改前端角色、直接请求 API 均不能提升权限。
- [ ] 面试人页面、API、SSE 和缓存均不包含任何内部笔记或评价。
- [ ] 重新邀请后旧身份不能继续读取推送或提交离线操作。

### 13.2 在线协作与业务

- [ ] 新便签、修改、拖动、标记、分组管理在两个考官窗口同步；本机正常连接下以通常 1 秒内可见为验收目标。
- [ ] 非作者不能编辑/删除便签，但可移动；同时移动后两个窗口最终一致。
- [ ] 删除有内容的分组需确认，便签进入“未分类”，系统分组不可删除。
- [ ] 独立讨论区可查看历史、引用便签定位、回复消息；删除原便签不破坏历史。
- [ ] 两人分别评价；仅一人提交、缺理由、缺分歧说明、非主考官确认均被服务端拒绝。
- [ ] 确认后所有业务写入均拒绝；重新开启保留历史结论并要求重新提交评价。
- [ ] 在线总结与 Markdown 对应同一报告版本；候选人不可读取或导出。
- [ ] 候选人准备状态同步到考官端；最终结论不向候选人披露。

### 13.3 离线和恢复

- [ ] 使用浏览器断网或停止服务模拟离线，便签编辑、移动、消息可排队，显示待同步。
- [ ] 页面刷新或关闭重开后，缓存和未同步文字仍存在；恢复服务后成功同步。
- [ ] 重发同一 opId 不重复生成便签、消息或回复，依赖操作按正确顺序执行。
- [ ] 对方删除便签、删除分组、完成面试、重新开启时，按第 9 节规则处理。
- [ ] 被拒绝的正文可在本地草稿中查看、复制，不静默丢失。
- [ ] 离线时无法假提交正式评价、假确认结论或假审批加入。

### 13.4 界面与交付

- [ ] 两个独立浏览器环境完成考官协作；第三个独立环境验证面试人界面。
- [ ] 电脑端完整操作，约 390px 手机视口能只读查看且无关键内容横向溢出。
- [ ] 深浅主题切换并记住偏好；拖动和菜单移动均可用。
- [ ] 空白和示例入口均可完成完整流程；示例不绕过审核和服务端持久化。
- [ ] 自动化测试通过，README 中的启动、演示、恢复步骤与实际一致。

重点自动化测试覆盖服务端角色越权、完成条件事务、重新开启、操作幂等及冲突结果；不为单纯样式或可直接观察的微小组件堆砌测试。

## 14. 风险、限制和处理

| 风险 | 处理与验收依据 |
| --- | --- |
| 当前执行沙箱禁止监听端口 | M0 在可监听环境验证，明确区分“代码准备完成”和“服务已运行” |
| 离线同步复杂 | 统一操作队列、版本检查、幂等记录，优先测试冲突矩阵 |
| 链接领取造成角色混淆 | 不同入口、一次性兑换、会话隔离、主考官审批与撤销 |
| 共享设备暴露内部资料 | 同一浏览器缓存按身份隔离；退出/撤销后不向新身份展示旧缓存 |
| 单机文件被删除或损坏 | 数据放固定目录，README 说明停止服务后备份整个 data 目录，恢复后验证 |
| 页面缓存版本与数据库变化不兼容 | 静态资源和 IndexedDB 设版本，升级不清除未同步文字，必要时进入恢复草稿模式 |
| 浏览器或包环境差异 | 核心运行不依赖下载；Chrome 优先完整验收，Firefox 做关键流程检查 |
| 范围继续扩展 | 本文作为实施基线，新增功能单列变更并重估，不压缩已确认核心功能 |

## 15. 本期明确不做

最终交付应包含可运行源码、简易 CLI、三角色浏览器界面、SQLite 持久化、示例数据入口、自动化测试、启动演示说明和本计划书。交付说明必须报告实际测试结果及未通过项。
