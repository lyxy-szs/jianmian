## 2. 浏览器端到端实测

启动服务后执行：

```bash
node scripts/browser-verify.mjs
```

脚本使用三个独立 Chrome 用户目录（主考官 / 副考官 / 面试人），完成了以下真实界面操作：

1. 首页创建示例面试，结果页输出三个不同角色链接；
2. 主考官通过一次性链接领取身份，进入面试板并看到 4 条示例便签与 2 条讨论；
3. 副考官在另一浏览器填写姓名提交申请；主考官在管理面板批准后，副考官自动进入；
4. 面试人领取身份并点击「我已准备好」，主考官端实时显示「已准备」；
5. 主考官新建重要便签，副考官窗口实测 **102 ms** 看到（目标 1 秒内）；
6. 副考官通过分组菜单移动主考官的便签，主考官窗口同步；再通过拖放事件把便签拖动到另一分组，位置一致；
7. 分组管理：新增分组 → 出现在便签墙 → 删除（确认后）→ 列消失；
8. 「重要」筛选只显示重要便签；
9. 讨论区发送、回复、引用便签；点击引用块可定位并高亮原便签；
10. 两位考官分别提交评价（等级不同），对方评价实时可见；
11. 主考官确认最终结论时因等级不同必须填写分歧说明，确认后便签墙只读；
12. 总结页与 `/report.md` 为同一版本（`round-1-final`），内容一致；
13. 面试人页面只显示「本次面试已结束」，不含最终理由或内部简介；其 IndexedDB 快照经检查不含便签、评价、内部简介；
14. 主考官重新开启面试，进入第 2 轮，评价恢复为草稿，历史结论保留；
15. 副考官离线新建便签 → 显示「待同步」→ 离线刷新页面仍能看到缓存与未同步便签 → 恢复联网后自动同步，主考官窗口看到该便签；
16. 冲突草稿：副考官离线修改便签，同时另一窗口在服务端删除该便签；恢复联网后修改被拒绝，正文保留在「草稿」中可查看，提示「便签已被删除」；
17. 390×844 手机视口：面试板与面试人页均无横向溢出，编辑/发送/准备按钮按预期隐藏，显示手机端只读提示；
18. 深色主题切换成功，刷新后仍保持。

脚本结束时会检查三个页面无未捕获脚本异常。最新一次运行输出：

## 5. 未覆盖或未完全自动化的部分

以下不阻塞本期核心验收，但应如实说明：

1. **原生拖动手势未做自动化**：无头 Chrome 无法稳定生成原生 HTML5 拖动，脚本使用 `DataTransfer` + `DragEvent` 触发同一套 `dragstart/dragover/drop/dragend` 处理器并验证最终位置；建议首次演示时人工拖动一次确认手感。
2. **Firefox 未在本轮实测**：Chrome 完整流程通过；Firefox 本机可执行文件存在，但本轮没有运行 Firefox 验收，跨浏览器差异未覆盖。
3. **跨设备/局域网/HTTPS 不在范围**：本期仅 `127.0.0.1` 本机验收。
4. **无屏幕阅读器与无障碍专项审计**：已提供键盘可用的「移动到分组」菜单、焦点样式与语义标签，但未做完整 WCAG 检查。
5. **未做长时间稳定性与压力测试**：单实例设计，未测试数十场面试同时在线、长时间 SSE 或大附件；附件本就不在范围。
6. **SSE 网络抖动专项**：已验证离线断线、恢复重连与事件补发，未做丢包/高延迟专项模拟。
7. **交付前数据清理**：历史测试数据已清空，`data/` 与 `exports/` 当前为空目录，交付时服务未运行；执行 `npm start` 会创建全新的数据库、管理凭据与邀请状态文件。
